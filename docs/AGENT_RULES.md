# قوانین ایجنت

## ممنوع
- نوشتن رمز، کلید یا اطلاعات محرمانه در کد یا داک. همه در `.env` (که در Git نیست).
- تغییر دستی ساختار دیتابیس. هر تغییر ساختار فقط با migration.
- خالی گذاشتن catch یا قورت دادن خطا بدون پیام.
- کامنت کردن، پاک کردن یا skip کردن تست برای سبز شدن.
- خواندن مستقیم متغیرهای محیطی در وسط منطق برنامه. فقط از طریق فایل تنظیمات.

## اول از انسان بپرس
- پاک کردن جدول یا ستون، یا تغییر اسم آن.
- هر تغییری در ورود، رمز، دسترسی‌ها.
- اضافه کردن کتابخانه‌ی سنگین یا سرویس بیرونی.
- تغییر قانون‌های کسب‌وکار که در FRDها آمده.

## استانداردهای فنی پروژه
- **استک و محدوده:** React (Vite + `react-router-dom`)، Python (FastAPI) و SQLite. از ساخت ویژگی‌های خارج از محدوده‌ی [PRD.md](product/PRD.md) خودداری کن.
- **خطاها و رابط کاربری:** همه‌ی پیام‌های خطا در بک‌اند و فرانت‌اند باید فارسی و شفاف باشند؛ نمایش خطای خام شبکه (`Failed to fetch`)، خطای خام ۴۲۲ (`[object Object]`) یا `alert()` مرورگر ممنوع است. هر صفحه‌ی لیست باید ۴ حالت (بارگذاری، خطا، خالی، متن بلند) داشته باشد و همه‌ی صفحات روی گوشی ریسپانسیو باشند.
- **بک‌اند و دیتابیس:** اعتبارسنجی ورودی‌ها مستقل در بک‌اند انجام شود و کد وضعیت HTTP درست (`200`/`201`, `400`/`422`, `401`/`403`, `404`, `409`) برگردد. تاریخ روز و `created_at` بر مبنای زمان محلی باشد (`toISOString()` برای تاریخ روز ممنوع). در SQLite همیشه `PRAGMA foreign_keys = ON` فعال و اتصالات داخل `try...finally` بسته شوند.
- **معماری فرانت‌اند:** تمام درخواست‌های HTTP فقط از `frontend/src/api/` و مسیر `/api` انجام شوند؛ توابع مشترک در `frontend/src/utils/`، کامپوننت‌های مشترک در `frontend/src/components/` و استایل‌ها در `frontend/src/styles/` باشند.
- **تحویل و گیت:** پیش از تحویل، تست‌های بک‌اند، `npm run lint` (۰ خطا و ۰ هشدار) و `npm run build` باید موفق باشند. هر تغییر روی یک branch جداگانه انجام شود و تنها پس از تأیید کاربر در `main` مرج گردد.
